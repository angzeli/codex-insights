## TAX-001 — evidence coverage

The task classifier still conservatively retains UNKNOWN. The analytics query now reports a
mutually exclusive origin-evidence partition: prompt-backed, originated-activity-only,
repository-fallback-only, and no-origin-evidence sessions. Explicit child threads and two UNKNOWN
diagnostics are separate dimensions: both UNKNOWN without prompt intent, and prompt-backed UNKNOWN
dimensions. Repository-name fallback is never represented as prompt intent.

The historical audit observed 258 sessions, 87 prompt-backed origins, 144 both-UNKNOWN sessions,
and only one prompt-backed domain opportunity. The current 284-session derived snapshot reports:

| Coverage | Sessions |
| --- | ---: |
| Prompt-backed | 95 |
| Originated activity only | 51 |
| Repository fallback only | 17 |
| No origin evidence | 121 |
| Explicit child threads (overlapping dimension) | 30 |
| Both UNKNOWN without prompt intent | 157 |
| Prompt-backed UNKNOWN dimensions | 1 |

The four evidence-basis rows sum to 284. The denominator changed as the source grew, so these are
not a longitudinal classifier-improvement claim. UNKNOWN actions remain 183 and logical prompts
were 3,430 at the final bounded query. No regex, label, confidence threshold, LLM, embedding, or
source-retention behavior changed. Focused taxonomy tests cover partition reconciliation, prompt
provenance, explicit child relationships, fallback-only evidence, missing evidence, and the one
prompt-backed rule-opportunity category.

## DOC-001 — human deep-doctor parity

The A wave had already made unknown source-shape diagnostics risk-aware, so this finding was
partially resolved. Human `doctor --deep` now adds a bounded `Indexed snapshot` table with:

- source/index status phrased as current, source advanced, or source/index mismatch without calling
  normal source advancement corruption;
- latest successful index time;
- missing rollout-reference and compatibility-warning counts;
- sorted token-lineage and event-provenance status counts.

The existing JSON keys remain stable, with the additive `latest_successful_index_at` field. Tests
cover a current snapshot and a synthetic source that advances by one missing-rollout row, at a
deterministic console width, and verify that private synthetic IDs/titles are absent. The final local
snapshot had 284 source and 284 indexed sessions, zero missing rollout references, zero compatibility
warnings, token lineage `ambiguous=22, inherited_prefix=8`, and event provenance represented only by
aggregate status counts.

## UI-001 — static accessibility

The offline, no-JavaScript visual design is unchanged. The six radio controls now transfer
`:focus-visible` styling to their visible labels, use named radio groups, and have 44-pixel minimum
targets. Light-theme small-text colors were adjusted; the lowest tested foreground/background
combination is 5.23:1. Every rendered data table has a visually hidden programmatic caption and
`scope="col"` headers.

A 1,000-session synthetic generation produced a 43,021-byte dashboard and a 21,704-byte weekly
report. Structural checks found 12/12 dashboard tables and 9/9 report tables with captions, 47 and
27 scoped headers respectively, two dashboard radio groups, and no script, link, or remote URL.
The existing 10,000-session dashboard regression also passed in the full suite.

## CI-001 — focused Windows coverage

Windows remains an intended platform because the runtime and public path model are platform-aware.
CI now has a narrow `windows-latest` matrix for Python 3.11 and 3.14. It builds and installs the
wheel, constructs only the committed synthetic source fixture, exercises version, doctor, index,
stats, timezone-aware usage, read-only/query-only source SQLite, guarded source-home output,
overwrite replacement, and benchmark startup. The benchmark reports peak memory as `unavailable`
when POSIX `resource` is absent while retaining all other measurements.

The workflow YAML parsed locally and the portable-memory regression passed. Remote Windows CI is
not validated until this branch is pushed; this report does not claim otherwise.

## MNT-001 — staged maintainability only

The finding is partially resolved and no additional implementation is justified in this wave. The
A work already established normalized source-kind parsing, explicit dirty-set planning, grouped
report/dashboard task queries, SQL tool aggregation, and measured indexes. Large orchestration files
remain (`indexer.py` is 3,111 lines and `adapters/codex_index.py` is 1,497), but line count alone is
not a correctness defect. A further split would be an XL, high-risk change to transactions,
idempotency, failure isolation, and source safety without a measured B-wave benefit. Future
extraction should remain attached to a concrete semantic change and characterization tests.
