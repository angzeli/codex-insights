`docs/audits/v1.1-forensic-audit.md`. It does not implement the report's B or C findings, bump the

## Finding dispositions

### SRC-001 — Structured client source is not normalized

**Disposition: FIXED.** The adapter now normalizes scalar and structured sources into `ClientKind`
and bounded `SubagentSourceKind` values. Only an explicit structured spawn reference supplies
`source_parent_session_id`; model, role, guardian names, and other heuristics never invent a parent.
Unknown or malformed structured values fail closed for user authorship, and the raw structured
encoding is neither persisted nor displayed.

- **Invariant:** source-specific structured metadata stops at the adapter boundary; analytics,
  filters, JSON, exports, and prompt authorship consume stable normalized fields.
- **Migration:** schema 17 adds the three normalized fields, converts recognized legacy scalar
  values conservatively, and clears legacy structured `client_source` text.
- **Regression evidence:** scalar CLI/editor, known spawn/guardian, future-field, malformed, missing,
  migration, filter/export, and prompt-authorship cases in `tests/test_source_normalization.py`,
  `tests/test_indexer.py`, and `tests/test_database.py`.
- **Measured aggregate:** the audit found 32 unstable raw structured source strings. The current
  aggregate-only smoke exposes five bounded concepts instead: 95 editor sessions, 189 subagent
  sessions, 30 explicit `thread_spawn`, 159 `other` subagent sources, and 30 explicit parent
  references. The source population advanced since the audit, so this is not a same-row percentage.
- **Commit:** `649eb4dec61d2d207ee7f4a3a7d6d7c29813f00c`.

### OUT-001 — LOW lifecycle evidence dominates success analytics

**Disposition: FIXED.** Lifecycle status is stored separately from task outcome. A nearly universal
turn-completion marker no longer proves success. Completion with originated edit evidence produces
LOW `partial`; completion without task evidence remains `unknown`. User-facing aggregates now expose
strongly evidenced non-UNKNOWN HIGH/MEDIUM outcomes separately from broad compatibility counts.

- **Invariant:** source lifecycle describes turn state; task success requires task-relevant
  originated evidence. UNKNOWN may increase when certainty is not defensible.
- **Migration/versioning:** schema 18 adds `lifecycle_status` and `strongly_evidenced`; classifier v2
  reconciles prior rows deterministically.
- **Regression evidence:** completion-only, edit-plus-completion, validation, recovered failure,
  abort, commit, dashboard/report, and confidence-coverage cases in `tests/test_outcomes.py`.
- **Measured aggregate:** the audit baseline had 202/258 LOW successes driven by lifecycle plus weak
  activity. In the current 284-session snapshot, outcomes are 200 UNKNOWN, 65 LOW partial, 13 HIGH
  abandoned, 5 HIGH failed, and 1 MEDIUM success; 19 are strongly evidenced. Lifecycle independently
  reports 271 completed turns and 13 aborted turns. The population changed, so these values show the
  semantic effect rather than a controlled rate comparison.
- **Commit:** `9c69872398db0429b96f6ebff30f808a2c8c34a4`.

### IDX-001 — Unchanged indexing pays global reconciliation cost

**Disposition: FIXED.** Indexing now constructs a deterministic invalidation plan from parsed or
metadata-changed sessions, topology branches, repository identity/version changes, classifier
versions, and Git ref-state changes. Outcome, feature, taxonomy, Git, repository, and coverage work
runs only for affected dependencies. A clean run copies the previous coverage snapshot instead of
globally recomputing it. Source discovery remains intentionally O(N).

- **Invariant:** an unchanged source produces no new/updated rows and identical derived coverage;
  every characterized dependency mutation reaches its required reconcilers.
- **Regression evidence:** empty dirty sets, one-session changes, parser/classifier invalidation,
  topology/repository propagation, coverage equivalence, and stage-timing JSON in
  `tests/test_indexer.py` and `tests/test_benchmark.py`.
- **Measured baseline/after:** the audit's 10k profile measured 4.932 s unchanged and 5.476 s for one
  changed rollout. The final profile measured 3.227 s and 4.013 s respectively, despite the later
  synthetic Git fixture adding a second commit per repository. At 10k the unchanged feature,
  taxonomy, outcome, repository, and Git reconciliation stages were effectively no-ops; source
  discovery remained 1.227 s. Timing comparisons are local diagnostics, not portable guarantees.
- **Commit:** `4a4711d5ff8df801d6788a33f794d11a31156d93`.

### DIA-001 — Unknown-source diagnostics are high-volume but low-actionability

**Disposition: FIXED.** Content-free observations are classified as `field_passthrough`,
`recognized_ignored`, `semantic_gap`, `tool_result_gap`, `lifecycle_gap`, or `unclassified`.
Diagnostics expose occurrences, affected sessions, first/last observation, newly-seen state, and
capability impact. Known consumed signals are classified rather than presented as uniformly
unsupported. No diagnostic stores a field value or raw payload.

- **Invariant:** high structural volume cannot obscure low-volume semantic risk, and new unknown
  names remain visible in an unclassified bucket.
- **Migration/versioning:** schema 19 adds category/impact/run provenance; parser v11 deterministically
  reclassifies source observations.
- **Regression evidence:** old/new runs, recognized ignored fields, high-risk low-count shapes,
  trend state, human/JSON doctor output, and raw-value non-persistence in `tests/test_compatibility.py`
  and `tests/test_cli.py`.
- **Measured aggregate:** current deep diagnostics partition 618,553 observations into 298,277 field
  passthrough, 317,598 recognized ignored, 594 semantic gaps, 1,686 tool-result gaps, and 398
  lifecycle gaps. The highest surfaced tool-result gap affects 7 sessions despite much larger
  harmless structural totals. Source/index counts agree at 284 and integrity is OK.
- **Commit:** `0730fe36682f706fdbd1a0f3212d6f9b593e100f`.

### GIT-001 — Git LOW candidates are broad and historically unstable

**Disposition: FIXED.** HIGH still requires exact originated successful result-hash evidence.
MEDIUM now requires one compatible successful candidate, bounded graph proof that it descends from
the session-captured starting SHA, and no concurrent session. Present checkout branch state is not
historical evidence. LOW candidates are capped at five per action and twenty per session, with
considered/persisted/omitted coverage. Read-only ref-state fingerprints invalidate only repositories
whose Git state or algorithm version changed.

- **Invariant:** time-only evidence never becomes HIGH or MEDIUM; siblings/concurrent sessions and
  current branch switches cannot manufacture certainty; omitted LOW candidates remain countable.
- **Migration/versioning:** schema 20 adds candidate summaries and repository reconciliation state;
  Git correlation v2 reconciles existing associations without deleting the index.
- **Regression evidence:** exact/abbreviated hashes, starting-SHA ancestry, concurrency, branch
  switching, detached/moved cases, large candidate windows, candidate caps, and idempotency in
  `tests/test_git_correlation.py`. The end-to-end generated corpus now contains a valid ancestry case.
- **Measured aggregate:** the audit snapshot persisted 581 LOW timing rows. The current, larger
  snapshot considered 12,305 timing candidates, persisted 167 bounded LOW rows, and explicitly
  recorded 12,138 omitted candidates across 14 affected sessions; it retained 5 HIGH and promoted
  no current real candidate to MEDIUM without the required ancestry evidence.
- **Commit:** `0d0b0751ce584fdf8543a3eb6fc557d4fdcde6ea`.

### SQL-001 — Query and orchestration structure repeats avoidable work

**Disposition: FIXED for the measured paths.** Schema 21 materializes the documented tool activity
time fallback and adds measured session/tool/category/Git time indexes. Tool summaries and grouped
command counts aggregate in SQL. Reports and dashboards use one grouped repository-task query rather
than N+1 per-repository task calls. Public payloads and numerical semantics are unchanged. A larger
shared-connection refactor was not needed for this finding and remains outside this focused wave.

- **Invariant:** time filters retain explicit event-time/session-start fallback semantics; SQL and
  grouped-query results equal previous public aggregates; repository/model/global sums reconcile.
- **Migration:** schema 21 backfills `effective_occurred_at` from `occurred_at` or session start and
  adds four indexes. Catalogue start-time changes refresh timestamp-less tool rows.
- **Regression evidence:** migration backfill, rollback coverage, `EXPLAIN QUERY PLAN` index use,
  tool/provenance/category invariants, grouped-versus-individual repository task equivalence, and
  report/dashboard tests in `tests/test_database.py`, `tests/test_tools.py`, and
  `tests/test_taxonomy.py`.
- **Measured baseline/after:** the prior 10k reference reported 4.740 s report and 5.036 s dashboard;
  the final profile measured 5.117 s and 7.513 s. This is not treated as a speedup claim because the
  Python version, runtime load, schema indexes, and generated Git history differ. The defensible
  improvement is structural: query plans use the named time indexes, tool rows are not transferred
  solely for Python counters, and repository task query count is constant rather than N+1.
- **Commit:** `275879157510d15fcecc33dda686bbefd7d5fe16`.

## Migration and validation evidence

Schema migrations 17 through 21 are forward-only and target only the derived database. Tests cover
representative migration from released schemas, data preservation, schema-20 tool-time backfill,
and transactional rollback on migration failure. No database reset is required.

Final post-correction validation used the repository's Python 3.11 virtual environment with
`PYTHONPATH=src` because this checkout intentionally remained uninstalled:

- `python -m pytest`: **255 passed in 16.16 s**;
- `python -m ruff check .`: **passed**;
- `python -m mypy src`: **passed, 55 source files**;
- focused synthetic end-to-end workflow: **passed**, including source-byte mutation invariants;
- controlled synthetic re-index: **120 discovered, 0 new, 0 updated, 120 unchanged, 0 skipped,
  0 failed**;
- 1k/5k/10k benchmark unchanged modes: **996/4,977/9,953 unchanged**, with only the deliberate
  4/23/47 missing rollout references skipped and zero failures;
- changed modes: exactly **1 updated** valid rollout at every scale and zero failures.

| Sessions | Fresh | Unchanged | One changed | Unchanged speedup | Slowest query |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 6.985 s | 0.508 s | 0.652 s | 13.8x | 0.043 s |
| 5,000 | 40.426 s | 1.371 s | 1.853 s | 29.5x | 0.214 s |
| 10,000 | 84.802 s | 3.227 s | 4.013 s | 26.3x | 0.580 s |

The bounded developer-only real smoke selected one read-only state database, discovered 284
rollouts/sessions, migrated and reclassified 258 existing derived sessions plus 26 new source
sessions, and reported zero failures. The source remained live while the harness ran: its immediate
second pass observed 282 unchanged and 2 updated sessions rather than a false unchanged-source
claim. Afterward deep diagnostics showed source/index count 284/284, zero stale sessions, zero parse
failures, schema integrity `ok`, and token data for 283/284 sessions. Exact unchanged idempotency is
therefore established by the controlled synthetic corpus; the live two-session movement is reported
as an external-state caveat, not a regression.

## Remaining risks and deferred scope

- Codex local storage remains undocumented. Parser categories are versioned observations, not an
  upstream contract.
- Outcome and Git coverage remains deliberately conservative; UNKNOWN, LOW, ambiguous, and omitted
  states are expected.
- Source discovery/stat remains O(N), and reports/dashboard still use separate public analytics
  calls even though the measured N+1/task and Python tool-aggregation paths were removed.
- Local benchmark times are not cross-machine service-level objectives.
- The original B findings remain untouched: TAX-001, DOC-001, UI-001, REL-001, CI-001, and MNT-001.
- The original C finding CLI-001 remains untouched.
- Previously resolved S findings were not revisited except that their stable command identity and
  derived-index safety invariants continued to be exercised by existing tests.
- Package version remains 1.1.0. No push, tag, release, or remote CI run belongs to this wave.
