## Migration and compatibility

**PASS.** A database created by the exact released `v1.1.0` code at schema 16 was populated from a
120-session deterministic corpus and migrated to schema 21. Counts were preserved for sessions,
usage, lineage, token events, event provenance, prompts/FTS-backed prompt rows, commands,

Forward-compatibility tests covered scalar and structured client/editor/subagent sources, unknown
future-compatible records, renamed catalogues, changed tool encodings, partial files, semantic token
drift, and previous-good recovery. `doctor --deep` remained bounded and content-free in both human
and JSON forms.

## Evidence semantics

- **Outcomes:** lifecycle completion alone remained UNKNOWN without task evidence. Validation,
  commit, recovered failure, failure, abort, edit-only, and inherited-evidence cases retained their
  conservative classifications.
- **Git:** HIGH required originated result-hash evidence; MEDIUM required captured-start ancestry;
  LOW candidates remained capped with explicit omitted counts. Inherited evidence did not create a
  child HIGH association.
- **Taxonomy:** prompt-backed, activity-only, fallback-only, and no-origin-evidence populations were
  mutually exclusive and reconciled to the selected population. UNKNOWN was not broadened away.
- **Queries:** effective-time indexes were selected by query-plan regressions; repository task
  queries stayed grouped rather than N+1; global, repository, model, report, dashboard, and export
  token totals reconciled in the deterministic integration test.
